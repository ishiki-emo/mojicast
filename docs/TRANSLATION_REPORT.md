# ローカル翻訳の実測レポート — 配信字幕をCPUだけで多言語化する

[Mojicast](https://github.com/ishiki-emo/mojicast) は、配信の音声をその場で文字起こしして
字幕にするツールです。その一部として、日本語の字幕を英語・中国語・韓国語・
インドネシア語へリアルタイム翻訳しています。**クラウドAPIを使わず、CPUだけで、
配信中に動かす**という条件でどこまでできるかを実測した記録です。

同じような仕組みを作ろうとしている方の参考になればと思い、うまくいった手だけでなく
**解けなかった問題**も含めて書いています。

（最終更新: 2026-08-24）

---

## 1. 前提 — この条件だから、この結論になる

結論は制約から出ています。条件が違えば答えも変わるので、先に置きます。

| 制約 | 理由 |
| --- | --- |
| **ローカルで動く** | 配信の音声を外部へ送らない。オフラインでも使える |
| **リアルタイム** | 喋ってから字幕が出るまで待たせない |
| **無料・商用可** | 配信で使う以上、ライセンスは商用利用を許すものに限る |
| **CPUのみ** | 配信中の GPU はゲームとエンコードで埋まっている |
| **他ソフトと共存** | OBS・ゲームと同じPCで動く。CPUを独占できない |

**GPU を使わないのが最大の制約**です。配信中は GPU が最も混んでいるので、
字幕のために取り合うと本末転倒になります。結果として「CPU で 100ms 前後」という
予算の中でモデルを選ぶことになりました。

---

## 2. 採用した構成

| 方向 | モデル | サイズ | ライセンス |
| --- | --- | --- | --- |
| 日 → 英 | [FuguMT](https://huggingface.co/staka/fugumt-ja-en) | 約120MB | CC BY-SA 4.0 |
| 日 → 中・韓・インドネシア | [M2M-100 418M](https://huggingface.co/facebook/m2m100_418M) | 約470MB | MIT |
| 中国語の地域表記 | OpenCC | 同梱 | Apache-2.0 |

実行は [CTranslate2](https://github.com/OpenNMT/CTranslate2) の int8 量子化です。
PyTorch / transformers は配布物から外しています（起動が速く、配布サイズも小さい）。

### なぜ英語だけ専用モデルなのか

**日本語発の翻訳は、英語以外の選択肢が極端に乏しい**からです。日→英には FuguMT の
ような専用モデルがありますが、**ja→zh / ja→ko / ja→id の公式な専用モデルは存在
しません**（Helsinki-NLP にあるのは `zh→ja` のような逆方向です）。

そのため多言語側は「100言語を1つでこなす」M2M-100 に頼ることになります。同じ容量を
100言語で分け合うので、**専用モデルより不利な戦い**になります。後述の速度差と
失敗率の差は、ほぼこの構造から来ています。

---

## 3. 実測

実配信の文字起こし **4,766行**（原文の平均13.5字）を、**本番と同じ関数**へそのまま
流しました。ベンチ専用の経路は通していないので、利用者が実際に見る品質です。

- 測定機: Ryzen 7 9800X3D / Windows 11 / CTranslate2 int8
- 設定: 現行のまま（英訳 beam=8 / 韓国語 beam=4 / 中国語・インドネシア語 beam=1）
- スクリプト: [bench/bench_translate_langs.py](../bench/bench_translate_langs.py)

| 言語 | モデル | 速度 | 訳が出ない | `<unk>` | 記号のみ | 捏造 | 反復暴走 | 平均字数 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 英 | FuguMT | **18.9ms** | 5 (0.1%) | 0 | 0 | 5 | 1 | 27.6 |
| 中 | M2M-100 | 115.2ms | 88 (1.8%) | 65 | 23 | 0 | 4 | 8.9 |
| 韓 | M2M-100 | 167.4ms | 79 (1.7%) | 75 | 4 | 0 | 8 | 15.9 |
| インドネシア | M2M-100 | 115.8ms | 0 (0.0%) | 0 | 0 | 0 | **38** | 32.3 |

モデルのダウンロードサイズは FuguMT 約120MB / M2M-100 約470MB。常駐メモリは英訳ONで
+309MB、中国語訳を足すと構成全体で約1.5GB です（[bench/README.md](../bench/README.md)）。

### 読み取れること

**専用モデルは別格です。** 英訳は M2M の **6〜9倍速く**、失敗率も1桁違います。
ja→en だけ専用モデルが存在するという構造が、そのまま数字に出ています。

**汎用モデルでも 2% は切れます。** 中国語1.8% / 韓国語1.7%。韓国語はもともと
**10%以上が訳せず原文へ倒れていました**が、探索幅を広げて 1.7% まで下がりました
（後述）。モデルを替えずに解決した部分です。

**失敗の型は言語ごとに違います。** ここが予想外でした。

- 中国語・韓国語は「**訳が出ない**」型（語彙外＝`<unk>` が主因）
- インドネシア語は訳が出ないケースが**ゼロ**なのに、**反復暴走が38件**と突出

同じモデル・同じ設定でも、**言語によって壊れ方が変わります**。実はインドネシア語には
反復抑止の `repetition_penalty` を効かせていません（中国語・韓国語で問題が出たときに
その2言語だけ対処した）。**先に困った言語だけ手当てすると、後から入れた言語に穴が
残る**という、よくある落とし穴を踏んでいます。

### 同じ原文を4言語で

```
定期配信のお時間でございます。
  英  It is a regular stream time.
  中  定期直播时间。
  韓  정기적으로 배달할 때가 있습니다.   ← 「配信」が「배달(配達)」に化ける
  ID  Terdapat waktu untuk live stream.

二月が終わっちゃいます。なんということでございましょうか。
  英  February is over. What do you mean?
  中  二月就结束了,怎么办?
  韓  2월이 끝났는데 어떻게 해야 할까요?
  ID  Bulan Februari sudah berakhir, apa yang harus kita lakukan?
```

上は**業界語の誤訳**の例です。「配信」を韓国語モデルが「配達」と解釈しています。
用語辞書で守るべき語が、まだ守れていません。

下は**文が完結している**ケースで、4言語とも問題なく訳せています。裏を返すと、
**入力が整っていれば汎用モデルでも十分使える**ということです。次章の失敗は、
その多くが「入力が整っていない」ことに起因します。

## 4. 失敗の仕方と、その扱い

実際に配信で使うと、翻訳は**間違えるのではなく壊れます**。しかも壊れ方には型が
あります。ここが一番の知見でした。

### 4.1 訳が出ない — 字幕が消えるのではなく、原文へ倒す

語彙外の語が入ると `<unk>` を含む訳文が出ます。また反復抑止の副産物で、訳が
「。」だけの断片になることもあります。**どちらもそのまま字幕に出すとゴミ**です。

対処は「空とみなして、原文（日本語）を出す」。翻訳できなかったことを利用者に
悟らせず、少なくとも日本語字幕は途切れません。

> **教訓**: 失敗時のフォールバック先を「何も出さない」にしてはいけません。
> 配信中に字幕が無言で消えるのが、いちばん困る壊れ方です。

### 4.2 捏造 — 言っていないことを足してしまう

**原文に無い言葉を、モデルが自信満々で作ります。** 実測では英訳の 0.19% に
罵倒語の捏造がありました。数字は小さく見えますが、配信で何度も出れば事故に繋がります。

```
でガチな方の龍角さんは
  → And the slutty one, mr. dragon horn!    ← 原文に無い罵倒語
二十五すごい。隅田さんの
  → 25 훌륭한 혜택, 김정은                   ← 人名が「金正恩」に化ける
```

**入力が壊れているほど捏造が増えます。** 音声認識の誤りや、途中で切れた文を
渡すと、モデルは文脈を「補って」しまいます。

対処は2つ。**原文と訳文を突き合わせて、原文に対応がない罵倒語なら訳ごと捨てる**
（そして原文へ倒す）。もう1つは**探索幅を広げる**ことで、これは次章に書きます。

> **原則**: 精度より忠実性。「言っていないことを出さない」を、
> 「なるべく訳す」より優先します。

### 4.3 反復暴走 — 同じ語が止まらない

相槌や繰り返しの口語（「あれですよ、もうあれですよ」）を渡すと、
`是的,是的,是的,…` と延々続く出力になります。実配信3,298文で90件発生しました。

`repetition_penalty=1.2` だけでは残るので、**3-gram の再出現を禁止**
（`no_repeat_ngram_size=3`）して確実に断ち切りました。これで0件です。速度差も
訳文の劣化もありませんでした。

### 4.4 解けなかったもの

正直に書きます。**次の3つは手を尽くして解けませんでした。**

**行の途中で切れた文**。音声認識は「一区切り」で行を出すので、**行の境界と文の
境界が一致しません**。倒置や言いよどみがあると、こうなります。

```
終わっちゃいますよ。なんと二月が
  英  It's over. february is              ← 途中で切れたまま出る
  韓  2월이 끝나고, 2월은 어떻게 되나요?    ← 「2月はどうなりますか?」と足される
```

原文には「二月が」までしかないのに、韓国語では疑問文が生まれています。**足りない
情報をモデルが補う**ためで、4.2 の捏造と同じ根です。行を結合する・訳を抑止する・
句点を補う——すべて試して、どれも別の副作用が出ました。

**口語の正規化**。縮約形（「してる」→「している」）を展開してから翻訳すれば改善
するかと思いましたが、**改善と悪化が拮抗**しました。形態素解析を入れるほどの
見返りはありません。

**伏せ字**。利用者が指定した伏字（`○○○`）は日本語字幕では守られますが、
**翻訳では破られます**。`○` を未知の記号として扱い、文脈から適当な語で埋めるためです
（中国語・韓国語では「2010年」「十月」など数字に化けます）。現在は未対策で、
「伏字対象語を含む行は訳を出さない」方向で検討しています。

## 5. 効いた手

### 5.1 int8 量子化 — 3倍速く、メモリは3分の2に

| | fp32 | int8 |
| --- | --- | --- |
| 英訳の速度 | 28ms | **9ms** |
| 常駐メモリ | 460MB | **309MB** |

CTranslate2 は実行時に `compute_type` を選べるので、**モデルの再変換も再配布も不要**
でした（`float32` → `int8_float32` の1行）。訳文は fp32 と 62% 一致で、品質は互角です
（fp32 が文の後半を落とす例が int8 では残る、といった逆転もあります）。

> **落とし穴 — ただし翻訳では起きていません**
>
> **CTranslate2 の int8 は、古いCPUでも壊れていません。** VNNI 非搭載のCPU
> （Intel 第10世代まで）を含め、翻訳の出力が崩壊した報告はありません。
>
> 壊れたのは**別系統の量子化**です。同じアプリに載せている句読点モデル（日本語BERT）
> を、ONNX Runtime 向けに自前で動的量子化（U8S8・per-channel・`reduce_range` 未指定）
> したところ、VNNI 非搭載のCPUで出力が崩壊しました（積和が int16 で飽和するため。
> 全文字に「。」が付く形で表面化）。音声認識に使っている int8 モデルも同じCPUで
> 正常に動いていたので、**量子化の実装によってリスクが違う**ということです。
>
> - CTranslate2: 実行時に `compute_type` を選ぶ方式。**実績あり**
> - `onnxruntime.quantization` で自前変換する場合: `reduce_range` の扱いに注意
>
> そして**開発機が新しいCPUだと絶対に再現しません**。古いCPUで確認できる経路
> （報告者に試してもらう、壊れ方を模したテストを置く等）を必ず用意してください。

### 5.2 探索幅（ビーム）— 速度を少し払って、捏造と失敗を減らす

**greedy（beam=1）は訳を1本しか辿らない**ので、反語や主語を取り違えたまま確定します。

```
このボス強すぎませんか、もう10回も負けてます。
  greedy  I'm afraid this boss is too strong,      ← 言っていない「恐れる」
  beam=8  Don't you think this boss is too strong,  ← 反語を汲む
```

**言語ごとに最適値が違いました。** 英訳は beam=8（+4.7ms で捏造が半減）、韓国語は
beam=4（+38.7ms で「訳が出ない」が 10.4% → 1.6%）、中国語は greedy のまま
（元の失敗率が低く、上げても中身は捏造の穴埋めが目立った）。

**大きいモデルほど探索幅は高くつきます。** 英訳（60MB）が +4.7ms で買えるものを、
M2M（468MB）は +38.7ms 払う必要がありました。

### 5.3 用語辞書 — 固有名詞と業界語を守る

配信のスラング（「草」「凸」など）は、そのまま訳すと意味不明になります。翻訳前に
置換する辞書を持たせました。また**英訳で大文字始まりになった語を、中国語・韓国語の
訳でも保護**しています（人名が音写で崩れるのを防ぐため）。

## 6. まとめ

- **GPU を使わない前提が、モデル選択のすべてを決めました**
- 日本語発の翻訳は**英語だけが恵まれています**。他言語は汎用モデルに頼らざるを得ません
- 翻訳は間違えるのではなく**壊れます**。壊れ方に型があるので、型ごとに受け止める
- **失敗時に原文へ倒す**設計が、いちばん効きました
- 量子化と探索幅の調整は、**モデルを替えるより費用対効果が高い**場面が多くありました
- 「言っていないことを出さない」を、「なるべく訳す」より優先しています

実測に使ったスクリプトは [bench/](../bench/) にあります。
