# 短い発話の取りこぼし：変更前後の比較（2026-11-05）

最小発話時間を **0.25秒 → 0.15秒** に変更した。しきい値0.5、無音区切り300ms、認識モデルは変更していない。
`engine.VAD_MIN_SPEECH_SEC` を実装と既存VADベンチで共有する。

## 条件

- sherpa-onnx 1.13.8、同梱 `silero_vad.onnx`。
- ReazonSpeech k2 v2、int8-fp32、ホットワードなし、前後0.9秒の無音パディング。
- 48kHzの既存録音 `20260708.wav`（78.1秒）を16kHzにリサンプリング。
- Microsoft Haruka Desktopによる10種類 × 2速度の合成音声20件。
  「はい／うん／え／あ／そう／いや／ね／おい／待って／ありがとう」。
- 合成音声の音量閾値による有音範囲は約0.096〜0.554秒。これはVADの判定時間そのものではない。
- 各音声に同一の処理を適用し、最小発話時間だけ0.25、0.15、0.10秒に変えた。
- 比較対象は認識直後の文字列。単語置換・数字正規化・句読点・翻訳・UI表示は対象外。
- 実装の `_build_vad(300)` が比較用0.15秒と同じ区間・同じ音声サンプルを出すことを、録音・合成音声20件・雑音3件で照合済み。

## 短い合成音声20件

| 指標 | 変更前0.25秒 | 採用0.15秒 | 参考0.10秒 |
|---|---:|---:|---:|
| 発話検出された件数 | 3 | 12 | 18 |
| 空でない認識文が出た件数 | 3 | 12 | 18 |
| 入力テキストと完全一致 | 3 | 10 | 13 |
| VADを通さない認識結果と一致 | 3 | 12 | 18 |

「え→えっ」「ね→ねっ」等の表記差は完全一致に数えていない。
VADを通さない認識結果は正解ラベルではなく、切り出し前後の比較用。
20件ともVADなしでは文字が出たため、今回の合成音声での無出力はVAD段階に切り分けられた。

通常速度の例：

| 入力 | 有音範囲の目安 | 変更前 | 採用後 |
|---|---:|---|---|
| はい | 0.195秒 | 検出なし | はい |
| うん | 0.206秒 | 検出なし | うん |
| そう | 0.271秒 | 検出なし | そう |
| おい | 0.186秒 | 検出なし | おい |
| あ | 0.143秒 | 検出なし | 検出なし |
| 待って | 0.414秒 | 検出なし | 検出なし |

音声全体の長さだけでなく、発話判定が継続する時間が重要。0.15秒で全件解決したわけではない。

## 既存録音78.1秒

全条件で16区間。0.15秒は15区間の認識文が変更前と完全一致した。
残る1区間は「皆様が得意だったのは何跳びですか」から「さて皆様が得意だったのは何跳びですか」に変化した。
開始位置は67.430秒から66.794秒へ移り、より早い音声が認識対象になった。
この録音には人手の正解書き起こしを用意していないため、追加された語の正しさ・全文字誤り率は未評価。

0.10秒では上記に加え、「二つ→一つ」「跳べば→飛べば」が変化した。
短音の検出数は0.10秒の方が多いが、既存の認識文への影響が小さかった0.15秒を保守的に採用した。

## 誤検出と回帰確認

- 無音10秒、白色雑音10秒（RMS約0.01）、合成クリック音10秒：全条件で検出0件。
- 実環境の咳・呼吸・キーボード・BGMは未評価。上記結果は雑音一般での安全性を保証しない。
- `test_engine_lifecycle.py`：57件成功。
- `git diff --check`：成功。
- 配布exeの再ビルド・実マイクを使ったGUI検証は行っていない。

## 再実行

日本語音声 Microsoft Haruka Desktop のあるWindowsで、プロジェクト直下から実行する。
検証用WAVはTEMPに生成し、元録音・モデル・ユーザー設定は書き換えない。
Python環境と音声合成エンジンへのアクセスが必要。

```powershell
./bench/generate_short_speech.ps1 -OutputDirectory "$env:TEMP/reazon-short-speech-20261105"
./reazonspeech-env/Scripts/python.exe -B bench/bench_short_speech.py --short-dir "$env:TEMP/reazon-short-speech-20261105"
./reazonspeech-env/Scripts/python.exe -B -m unittest discover -s tests -p test_engine_lifecycle.py
```

全区間の開始時刻・長さ・認識文、各短音の認識文は `short_speech_results.json` に保存。
問題が出た本人の実録音を使った改善率はまだ測定していない。今回確認できたのは、最小発話時間による取りこぼしの再現と、同一音声での改善。
