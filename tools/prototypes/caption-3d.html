字幕の奥行き試作

Mojicast 本体とは無関係の単独ページです。CSS の 3D 変形だけで、字幕を斜めに置いたり、古い行ほど奥へ下げたりした見え方を確かめられます。字幕は本体と同じ順序で出ます。認識途中の薄文字が伸びていき、確定すると句読点と登録単語の演出がついた行に置き換わり、そのあと英訳が付きます。下の枠が 1920×1080 のブラウザソースに相当します。

枠レイアウト（本体の既定レイアウトと同じ位置・大きさ・背景。枠ごと傾く）

「本体と同じく切り取る」にすると、行ごとの奥行き・Z からの組み立て・空間パーティクルが平らになります。枠ごとの傾きと厚みはそのまま効きます。リリックは独自の演出なのでここには入れていません。

試していて気づくこと

    
    
      
  • 角度を 30° 以上にすると、フチ取りがにじんで読みにくくなります。15〜20° くらいが実用的です。
    • 
      
  • 右寄せで右の壁にすると、手前の端が画面の外へはみ出しやすくなります。「ソースの枠」を表示して確かめてください。
    • 
      
  • 「行ごとの奥行き」は傾きが 0° でも効きます。奥の行が少し小さく中央へ寄るだけで、古い発言だとわかります。
    • 
      
  • 「前の行を押し下げる」にすると、話し始めた瞬間に過去の行が一段奥へ引くので、いましゃべっていることが伝わりやすくなります。代わりに画面が動く回数は増えます。
    • 
      
  • 枠レイアウトは枠ごと傾くので、背景や角丸も一緒に奥行きを持ちます。下部バーや上部バーのような横いっぱいの帯は、横に傾けると手前の端が画面からはみ出します。縦の傾きや床に流す型のほうが相性がいいです。
    • 
      
  • サイドログ・縦書き・ハーフのように画面の端に寄った枠は、画面の外側の端を軸にして回るので、内側へ向かって奥に倒れます。右の壁・左の壁の型がそのまま似合います。
    • 
      
  • 本体に入れるときの注意 4：枠の背景を文字と同じ 3D 空間に置くと、回転中や奥から来る途中の文字が背景の裏に入って半分欠けます。背景は同じ傾きの別の層に分けて後ろに重ねます。吹き出しは中を平らにまとめて、遠近を吹き出しの中だけで付けます。
    • 
      
  • 吹き出しはこの試作だと形を角丸だけにした簡略版です。本体の吹き出しは SVG で描いているので、入れるときは箱ごと傾ける方式にします。
    • 
      
  • 組み立て演出は、前回の表示と新しい文字列を突き合わせて差分だけ飛ばしています。認識途中が「せー」→「セーブ」と書き換わると、変わった部品だけが入れ替わって飛んできます。確定時も、句読点が入るところと登録単語だけが飛んできます。
    • 
      
  • 組み立て演出の動きは transform と opacity だけなので、GPU の合成だけで済みます。飛んでいる最中の部品が一時的に層になる程度で、負荷はほぼ増えません。
    • 
      
  • 読みやすさの面では、Z（奥行き）から来る部品がいちばん目立ち、X（横）がいちばん落ち着きます。しゃべりが速いと次々に飛んでくるので、時間は 400ms 前後が目安です。
    • 
      
  • 登録単語を面から手前へ浮かせる案は外しました。傾けた面の上で単語だけ Z にずらすと、カメラから見て横や上下に位置がずれ（視差）、10px 程度でもその単語だけ行がずれたように見えるためです。単語は面に乗せたまま、色・大きさ・動き・パーティクルで強調します。
    • 
      
  • 「スピン」は本体だと平らに縮むだけですが、3D の中では本当に奥行きを持って回ります。
    • 
      
  • 本体に入れるときの注意 1：登場アニメも単語の動きも transform を使うので、奥行きの translateZ と打ち消し合います。この試作では、奥行きと動きを別々の要素に掛け分けています。
    • 
      
  • 本体に入れるときの注意 2：色つきの登録単語は本体だと text-shadow を自前で上書きするので、そのままだと厚みが単語のところだけ消えます。試作では単語の光彩に厚みを足し直しています。
    • 
      
  • 本体に入れるときの注意 3：opacity や filter を 1 未満にした要素の中では 3D が平らにつぶれます。認識途中の薄文字を行ごと半透明にすると、Z からの組み立てが効かなくなるので、部品ごとに薄くします。
